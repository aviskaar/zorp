# erbga

A genetic algorithm for graph community detection, with a pluggable
objective.

This implements Rao, Janikow, Bhatia, and Climer, "Efficient Reduced-Bias
Genetic Algorithm (ERBGA) for Generic Community Detection Objectives",
MWAIS 2018 Proceedings 32, and the longer thesis of the same name. zorp's
author is that work's first author.

The crate knows nothing about zorp. It takes a graph and an objective and
searches.

## The idea

Encoding a clustering by labelling vertices means `k!` distinct
chromosomes describe the same clustering, so the search space is inflated
by a factor of `k!`. ERBGA encodes a clustering as the set of **removed
edges** instead. The connected components left behind are the clusters.

That buys two things. Label permutations disappear, and the number of
clusters does not have to be known in advance, because it falls out of
the cut.

## A correction to the source

The source states this representation describes each clustering "exactly
once". That is true of label permutations, which is the contribution, but
it is not true in general.

On a triangle, removing nothing and removing a single edge both leave one
component, because the two endpoints stay connected through the third
vertex. Any edge whose removal does not disconnect its component is
phenotypically a no-op, so the collapse factor is at least
`2^(|E| - |V| + c)` for `c` components, which is the circuit rank. It is
largest on dense graphs.

The redundancy is not harmful to the search, since neutral genotype
networks are usually benign or helpful, but the encoding is many-to-one
onto partitions rather than bijective. `Graph::partition` is what
canonicalizes, and the test suite asserts the true claim (distinct
partitions never share an encoding) rather than the overstated one.

## Benchmarks

Fixtures in `tests/data/` are generated by `tests/data/fetch.py`, which
verifies vertex and edge counts against Table 2 of the thesis before
writing anything, so a moved or changed upstream file fails loudly rather
than silently substituting a different network.

Targets are thesis Table 3, including the two networks the method did
badly on:

| Network | E/V | Best known | ERBGA |
|---|---|---|---|
| Karate | 2.3 | 0.420 | 0.420 |
| Dolphin | 2.6 | 0.529 | 0.445 |
| Political Books | 4.2 | 0.527 | 0.256 |
| Football | 5.3 | 0.605 | 0.073 |

Accuracy degrades monotonically with density across all four, with Gene
Repair enabled. That is worth knowing before building on this: the method
is strongest on sparse graphs.

The full benchmark is `#[ignore]` and slow. It is stochastic (the thesis
reports 4 of 25 islands reaching 0.420 on Karate, the rest near 0.397)
and the published numbers come from runs capped at 48 hours. What runs
unattended is a seeded, deterministic smoke test.

```
cargo test -p erbga --release --test benchmarks -- --ignored --nocapture
```

## Disputed parameters

Three values differ between the paper and the thesis, so both parameter
sets are provided and the benchmark reports both rather than one being
silently chosen.

| Parameter | Paper | Thesis |
|---|---|---|
| Random Population Rate | 0.25 | 0.85 |
| Tournament pool size | 3 | 7 |
| Dolphin result | 0.465 | 0.445 |

The thesis text supports the higher population rate: "tweaking the Random
Population Rate to be closer to 1 resulted in the improvement in the
quality of the initial set of chromosomes."

## Notes on this implementation

**Randomness is in-crate.** The benchmark is a regression test against
published numbers, so the sequence has to be stable across platforms and
releases. `rand`'s `StdRng` does not promise that. xorshift64* does the
job and keeps the crate dependency-free.

**Chromosomes are bit packed** into `u64` words, because efficiency is one
of the source's stated contributions and Rust's `Vec<bool>` costs a byte
per element, which would make that result impossible to reproduce and
would stream eight times the bytes through the hottest loop. `Chromosome`
is opaque, so the source's contiguous population layout can be adopted
later without touching any operator.
